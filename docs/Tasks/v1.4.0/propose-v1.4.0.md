# Propose v1.4.0

> **狀態:草稿(待 user 判斷)**。本版由 AI 依 user 需求(「掛 2 個 Worker 避免速度太慢」+「調整 UI」)評估後起草,格式對齊 `01-propose/01-propose-format.md`;user 批准後才走 `/propose-to-tasks` 拆解。

## 版本目標

v1.3.x 完成「一表一排程 + 增量偵測」後,本版聚焦**同步速度**與**同步體驗**兩個痛點:

1. **多表同步太慢**:一輪同步(手動全量 / 排程分組)內是**逐表序列**執行,總時長 = 全部表時間加總。本版讓同一輪內多張表**平行同步**(預設並行度 2,可調),多表輪次的總時長顯著下降。
2. **同步過程是黑箱**:觸發同步後只有一句「已送出」,使用者不知道跑到哪、還要多久,只能乾等或反覆重整。本版加**全域同步進度條**,任何同步進行中都能一眼看到進度。

> 評估結論(為何不是「多掛一個 worker 容器」):現行 worker 容器內 taskiq 預設已有 2 個子行程,能同時消化兩發「不同輪」的任務;慢的根源是**單一輪任務內部逐表 for 迴圈**。多掛容器對單輪速度毫無幫助,還增加同表互撞面。正解是「一輪內的表級平行」,不需要動 compose、不需要加基礎設施。

## In Scope

- **同輪表級平行同步**:一輪同步(手動全量 / 篩選 / 排程增量)內,多張表以固定並行度同時鏡像;並行度由環境變數控制,預設 2,設 1 即退回現行序列行為。單表失敗不中斷整輪、逐表 log、run 收尾統計等既有語意不變。
- **全域同步進度條**:
  - 任何同步(手動或排程)執行中,前端所有頁面顯示 sticky 進度條:已完成表數 / 總表數、成功 / 失敗 / 跳過計數;完成後自行消失。
  - run 建立當下即可知道總表數(分母),不必等收尾。
  - 新增查詢「目前執行中 run + 進度」的 API 端點,前端輪詢取得;不做 websocket。
- **run 明細頁即時更新**:執行中的 run 明細 / 逐表 log 自動輪詢刷新,run 結束即停(現況進頁一次不再更新,執行中看不到推進)。
- **runs 頁手動觸發按鈕修復**:「手動觸發(全部啟用表)」現仍呼叫 v1.3.1 已移除的 `POST /runs/trigger`,按下必 404 卻顯示成功字樣;改接現行同步觸發端點。

## Out of Scope

- **多 worker 容器水平擴充**(compose replicas / 第二個 worker service):評估無助於單輪速度,不做。
- **跨輪(多 run)併發控制重設計**:排程與手動同時觸發同一張表時,目標端由 DB 鎖序列化、結果仍完整,僅浪費一次重灌 — 現況已如此,本版不惡化也不專門治理。
- **同步演算法改變**:仍為 TRUNCATE + 整表重灌鏡像,不做 CDC / upsert 式增量搬運。
- **websocket / SSE 即時推播**:輪詢已足夠,不引入新通訊機制。
- **單表內部平行**(一張大表拆多段平行灌):風險高、收益侷限於極大表,不做。
- **通知告警、Coolify 正式部署調整**:沿用既有 Out of Scope。

## 對外承諾

- **速度**:同一輪多表同步的 wall-clock 總時長,較序列版明顯下降(理論上限 ≈ 1/並行度,受最大單表時間下限);單表輪次不變慢。
- **相容**:既有同步觸發 API(`POST /sync/all` / `/sync/{table}` / 篩選)的路徑、參數、回應契約不變;`etl_runs` / `etl_run_logs` 的欄位語意不變(runs 執行中可提前看到總表數)。
- **進度**:同步觸發後數秒內進度條出現,顯示「已完成 n / 共 N 表」並隨執行推進;失敗表數即時可見;結束後進度條消失、runs 清單可查收尾結果。
- **修復**:runs 頁「手動觸發(全部啟用表)」按下後實際入列執行(HTTP 202),新 run 出現在清單,不再 404。

## 風險與相依

- **來源 RDS 讀壓**:並行度 2 代表同時兩條整表串流讀;預設保守取 2、env 可調,異常時設回 1 即回到現行行為(安全閥)。
- **並行下紀錄一致性**:逐表 log / 快照更新在並行時的 DB session 使用須隔離(session 不可跨併發共用),屬技術風險,以既有測試 + 新增並行情境測試把關。
- **進度輪詢負載**:進度查詢為自有 DB 輕量聚合(不打 RDS),輪詢間隔取秒級,負載可忽略。
- **本專案跑法**:改碼後以 `docker compose up -d --build` 驗證(禁 start-dev)。

## 驗收標準

- 後端:`uv run ruff check .`、`uv run mypy .`、`uv run pytest` 全綠;新增測試涵蓋「並行度 > 1 時逐表 log / run 統計完整正確」「並行度 = 1 行為等同現行」。
- 前端:`npm run typecheck` 與 `npm run lint`(--max-warnings=0)通過。
- 手動(docker compose 環境):
  - 觸發全量同步,進度條出現且「已完成 / 總表數」隨執行推進,完成後消失;runs 清單見對應 run 收尾。
  - 同一批表,並行度 2 的同步總時長 < 序列(粗驗即可,看 run duration)。
  - 執行中進入 run 明細頁,逐表 log 自動增加,run 結束後停止輪詢。
  - runs 頁「手動觸發(全部啟用表)」回 202、新 run 入列,無 404。
  - 無執行中同步時,進度條不顯示;進度查詢端點回「無執行中 run」。
