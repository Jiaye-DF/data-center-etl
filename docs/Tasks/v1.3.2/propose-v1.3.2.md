# Propose v1.3.2

> **狀態:已實作**。本版由 user 口述需求逐項確認後直接實作(非先 propose 後開工),本文件為版本收斂紀錄,對齊 `01-propose/01-propose-format.md` 結構,供回溯與 code review。

## 版本目標

v1.3.1 完成「一表一排程」與逐表檢視後,本版聚焦**瀏覽 / 篩選體驗與營運可視性**的三個缺口:

1. **ETL 資料管理頁欄位不合語意**:target(ETL 產物)沿用 source 的「RDS 同步時間 / ETL 轉換時間」兩欄,而這兩欄只有 source 會被 `mirror_sync` 寫入,target 恆為空。改為顯示對 target 有意義的「快照時間」。
2. **排程管理 / 原始資料管理的進階篩選不足**:排程頁缺「資料總筆數」「排程時段」篩選;原始資料頁缺「筆數區間」與規模概覽。
3. **總覽頁只有導覽卡、無營運資訊**:改為「一眼看出同步健康 / 待處理 / 下一班 / 資料規模」的精簡儀表板。

全部改動**不新增資料源、不打 RDS**,聚合皆讀自有 DB;**未引入新套件**(cron 時段解析以既有欄位運算)。

## In Scope(已實作)

- **ETL 資料管理頁欄位改版**:`DatasetBrowser` 依 `dataset` 分欄——target 顯示單一「快照時間」(`snapshot_at`),source 維持「RDS 同步時間 / ETL 轉換時間」。後端 `TableSummary` 補吐 `snapshot_at`(nullable)。
- **排程管理頁**:
  - 欄位標題「業務名」→「**業務資料表名稱**」(對齊 source/target 頁)。
  - 進階篩選新增「**資料總筆數**」(全部 / 有資料 / 空表,對 `rds_table_meta.row_count`)。
  - 進階篩選新增「**排程時段**」(HH:MM 起訖,含端點)——合併 user 要的「排程時間 + 下次執行區間」;因現行排程皆為每日 cron,兩者等同每日執行時刻。後端以 `split_part(cron_expr)` 取分/時欄、`CASE` 保護非數字後換算 minute-of-day 比較(非每日純數字 cron 一律排除)。
  - 「僅啟用 / 停用符合篩選排程」批次操作**同步吃新篩選**(rows / 時段),與逐表列表命中集合一致。
- **原始資料管理頁**:
  - 進階篩選新增「**筆數區間**」(`row_min` / `row_max`,含端點)。
  - 新增「**統計摘要**」區塊(依當前 schema):總表數 / 有資料 / 空表 / 1000+ 表數。新增 `GET /datasets/{dataset}/summary` 端點。
- **總覽儀表板**:改寫 `(main)/page.tsx`,保留 4 張導覽卡,上方加四塊:
  - **同步健康**:最新一次 run 狀態 / 涵蓋表 / 成功 / 失敗 + 近 20 次成功率。
  - **待處理失敗表**:最新 run 若有失敗 → 列失敗逐表(可點進 run log);無失敗顯示「目前無待處理」。
  - **下一班排程**:啟用中排程數 / 總表數 + 下次執行(前端由啟用中相異 cron 以 `nextRunFromCron` 取最近一班)。
  - **資料規模 + 快照新鮮度**:source / target 各自表數分布 + 最近快照 / 同步時間。
  - 新增單一聚合端點 `GET /dashboard/overview`(讀 `etl_runs` / `etl_run_logs` / `schedules` / `rds_table_meta`)。

## Out of Scope

- **同步「總筆數」加總 / 趨勢圖**:`row_count` 為 bounded 探測(>1000 存 1001),加總會失真;儀表板與統計摘要一律以「表數分布 + 1000+ 桶」呈現,不做筆數加總、不放時序圖。
- **任意 cron 的後端下次執行計算**:需 croniter 類套件(技術棧鎖定,不擅自擴張);現行皆每日排程,以 minute-of-day / 前端 `nextRunFromCron` 涵蓋。
- **儀表板即時推播 / 自動刷新**:本版為進頁查詢一次,不做 websocket / 輪詢。
- **實體 DROP、通知告警、Coolify 正式部署**:沿用既有 Out of Scope。

## 對外承諾

- ETL 資料管理頁不再出現恆空的兩個時間欄,改看「快照時間」;source 頁行為不變。
- 排程管理頁可依「資料總筆數」「排程時段」篩選,批次啟停與篩選結果一致;業務名欄標題與其他頁一致。
- 原始資料管理頁可用筆數區間精篩,並在上方一眼看到該分類的表數分布(含 1000+ 桶),且不呈現會失真的加總數字。
- 總覽頁進站即可看到:同步是否出事、有無失敗待處理、下一班何時跑、source/target 規模與快照新鮮度;細節一鍵導向對應頁。

## 風險與相依

- **row_count 上限探測(1001)**:筆數區間 >1000 無法精確區分、加總會失真——UI 已標註「超過 1000 視為 1000+」,統計改用表數分布(誠實呈現)。
- **cron 時段篩選僅適用每日純數字 cron**:週期式(`*/5`)/ 非數字欄位一律排除於時段篩選(以 `CASE` 回 NULL 排除),現行排程皆每日故不受影響。
- **儀表板新鮮度**:進頁查詢一次,他處觸發同步後需重進 / 重整才更新(可接受;非即時監控台)。
- **本專案跑法**:改碼後以 `docker compose up -d --build` 驗證(禁 start-dev)。
